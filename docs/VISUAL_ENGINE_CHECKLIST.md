# TutorBoard — Visual Engine v2 Checklist

**Goal.** A general visual-reasoning workspace: *any* question → an LLM writes a
structured **scene** (JSON) → TutorBoard's engine turns it into a film-quality,
step-by-step animated explanation, with in-context doubts. No per-topic
templates: the AI composes general **primitives** and **actions** freely, the
engine guarantees layout, motion and correctness.
The bar is the v3 launch film (`promo-video/out/TutorBoard-Film-v3.mp4`).

**How to use this file.** Work top to bottom. A task is done only when its
*Done when* holds. Tick it, add a line to the progress log at the bottom.
Anything that needs a decision from the owner is marked 🟡.

## Baseline (2026-10-10)

| Area | Score | Why |
|---|---|---|
| Architecture | **55%** | Right idea (AI → JSON → orchestrator → GSAP → D3 plugins), but **three** parallel visual pipelines with three JSON formats (lesson `LessonSchema`, chat `VisualScriptSchema` + hardcoded fallback, artifact scene graph), lossy schema bridges, ~10 client renderers. |
| Maintainability | **40%** | God files (`Home.jsx` 2,125 lines, `conversationSlice.js` 1,110, `useTeachingMachine.js` 802), mixed JS/TS, no tests for the lesson pipeline or canvas engine, stale duplicates at repo root, ~20 flow-breaking bugs were only found at runtime. |
| UI / UX | **72%** | Strong, premium visual identity (the film used it as-is); good session panel, controls, doubt UX. Held back by state glitches and slow lesson generation. |
| Rendering | **45%** | Plugins work for arrays/trees/nodes; the AI chooses screen coordinates (0–1) so boards overlap or go empty; few primitives; no state-to-state transitions, no camera, basic timing. |
| Understanding (AI correctness) | **60%** | Frontier models write good explanations, but values/steps are guessed, not computed; schema failures cause retries. |
| Teaching quality | **55%** | Steps + narration + contextual doubts + resume are real differentiators; visuals often don't match the narration; no checks for understanding. |
| **Overall** | **≈54%** | |

Targets after this checklist: Architecture 85 · Maintainability 80 · UI/UX 85 · Rendering 85 · Understanding 85 · Teaching 85.

## Target architecture

```
question ─▶ Planner (LLM, tool calls) ─▶ Scene JSON (Scene Language v1)
                 │  tools: algorithm tracer · math · physics · chemistry · ML data
                 ▼
          Validate + repair loop (schema → semantic → layout dry-run) ─▶ stream beats
                 ▼
client:  Layout solver (relations → px) ─▶ Choreographer (motion tokens, morphs, camera)
          ─▶ GSAP timeline ─▶ primitive renderers (SVG/D3, KaTeX) ─▶ play / pause / step / seek
doubt:   scene state snapshot ─▶ Delta (actions on existing ids) ─▶ same executor
```

Principles: the AI never chooses pixels (relations + domain units only) · facts
come from tools, not guesses · motion quality lives in the engine, not the prompt ·
one scene format everywhere · new engine ships behind `ENGINE_V2` until it beats v1
on the eval set.

## Phase 4 — Doubts & interaction on v2

## Phase 5 — Teaching quality

- [x] **5.1** Check beats + recap: a beat may carry `check` {question, 2–4 choices, answer, explain} (validated: answer in range, not on the last beat; loose forms coerced). The lesson waits after that beat (`CheckCard`): right → why + Continue; wrong → the right answer, why, and **"Show me on the board"** (a Phase 4 board answer). Prompt rule: one check before the key moment in lessons of 4+ beats, and a recap beat at the end; goldens show the format. Component + validation tests. *Not yet seen in a live lesson (quota).* ✅ 2026-10-19
- [x] **5.2** Adaptive lessons: the planner gets the learner's level — beginners (or struggling on checks / high confusion / "granular" style) get more, smaller beats with terms defined and a slow key beat; advanced ("high-level" style / mastery) get 3–4 sharp beats. Level comes from check results in the chat path and the stored profile in socket sessions. Within a lesson a missed check slows playback a little, a right one restores it. ✅ 2026-10-19
- [x] **5.3** Narration: concise (≤ 40 words) and describing exactly what the learner sees (prompt rules 2, 10), now also "show why, don't state it" — a formula is the result of something the learner watched happen. **TTS timing drives beat length** on both paths: a step moves on only when its animation AND its narration have finished (spoken: the voice's end event; muted: reading time). The chat path also armed its own reading timer, which released steps ~5 s before the voice finished — removed (2026-10-20). ✅
